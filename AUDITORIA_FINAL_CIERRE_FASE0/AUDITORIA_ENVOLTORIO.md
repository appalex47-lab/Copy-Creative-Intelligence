# Auditoría de `ejecutar_script_verificado.sh`
Uso: `ejecutar_script_verificado.sh <SHA-256 de SHA256SUMS_CCI.txt aprobado externamente> <script.sql> [opciones psql]`. SHA256SUMS actual: `59c1186992bff6cfc752da6d4e71412de6bc9a53a50c535a9b055142a02f83ab`. Envoltorio: `8735b7dbaf1d16bdff1484342dc42476b5d0fa75166d265cdbfab26a6d1b634a`.
Controles: rechazo de symlinks; conjunto exacto de 10 archivos; copia a directorio privado 0700 y verificación `sha256sum -c --strict` sobre la copia (cierra TOCTOU); el hash de la guarda se toma de SUMS verificado; PGOPTIONS restringido; opciones peligrosas rechazadas (-f/-c/-L/-o/-1/-X/-v cci_*…); PATH fijo; se limpian PSQLRC/BASH_ENV/LD_*; destino contra `CCI_DESTINOS_APROBADOS`; limpieza con trap.
Casos WRAP-01…27 (0 ejecuciones): script/guarda alterados, SUMS regenerado, hash erróneo/ausente, guarda vacía/truncada/ausente, symlinks, cwd hostil, PATH/PSQLRC/BASH_ENV/LD_PRELOAD, variables CCI_* preestablecidas, PGOPTIONS extra, destinos, TOCTOU (25 ejecuciones con intercambio, pwned=0), 6 simultáneas, SIGTERM, permisos (usuario nobody), script ajeno. Todos PASS en el árbol final.
Limitaciones: el hash aprobado debe provenir de una fuente externa (no existe); un atacante con control del hash y de los archivos no se detecta; stdin no soportado (`\ir` relativo); ejecución directa con psql sin envoltorio sólo está protegida si el operador exporta el hash aprobado (GD-20: sin variables el preflight rechaza).
