# Control de secretos (`npm run check:secrets`)

Alcance: todos los archivos de la raíz (incluidos `.env*`, `.npmrc`, ejemplos y configuración) y, de forma recursiva, `src`, `tests`, `e2e`, `scripts`, `public`, `database`, `supabase` y `.github`. Funciona desde cualquier directorio y acepta una ruta opcional. No imprime valores (solo archivo, línea y tipo).
Detecta: archivos `.env`/`.env.*`/`.envrc` y nombres típicos de material secreto (`*.pem`, `*.key`, `id_rsa`, `credentials.json`…); JWT, cadenas de conexión, claves privadas, claves de Supabase (`sb_`, `sbp_`, `service_role`), Cohere, OpenAI/Anthropic (`sk-`), AWS, GitHub, Google, Slack, Stripe, npm, Hugging Face, Groq, SendGrid, `.npmrc`, cabeceras `Authorization` y asignaciones genéricas `…KEY/TOKEN/SECRET/PASSWORD=valor largo` (se ignoran marcadores como `your-…`/`example`).
**Limitaciones (análisis heurístico):** no mide entropía, no analiza el historial de Git, puede tener falsos negativos (formatos no listados, valores partidos) y falsos positivos; no inspecciona `docs/`, `evidencia/`, `evidence/` ni `AUDITORIA_*` (fuera de alcance); **no abre archivos comprimidos**: el script los lista como «NO inspeccionados» (hoy `AUDITORIA_FINAL_CIERRE_FASE0.zip` y `AUDITORIA_FINAL_INDEPENDIENTE_FASE0.zip` en la raíz; además hay ZIP versionados en `docs/fase0` y `ARTEFACTOS_REVISION_PUBLICACION`, fuera de alcance). No sustituye un escáner dedicado (p. ej. con historial completo) antes de publicar.
